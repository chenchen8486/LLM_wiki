# 领域归属评估与开源工程参考

- 日期：2026-09-10
- 性质：正式评估文档。由两轮对话分析（技术手段归属评估、设计初衷归属评估）合并修订而成，取代原对话记录体裁的版本。
- 依据：对主文档 `1_多媒体信息抽取：架构设想.md` 全文的理解，以及多轮联网检索核实（检索时间 2026-09-10），外部事实均附来源链接。
- 修订说明：相对旧版的三处实质修正。一，旧版结论只说归属 LLM 知识图谱构建，这只回答了手段层，不完整，本版改为目的层与手段层双层归属。二，旧版说最近的邻居是 GraphRAG 谱系，修正为分层表述：手段层邻居是 GraphRAG，形态层近亲是 Deep Research 类系统与 Elicit。三，补充 OSINT 情报分析与软件设计恢复（Design Recovery）两个领域的细节展开。其余判断经复核保留。

## 一、评估对象：这套架构要解决什么问题

　　评估归属前必须先钉死问题本身。这套架构建出来的是一个收集不同质量文档的知识库系统，用途是在没有源代码、没有原厂内部资料的条件下，把海量、参差、互相打架的公开文档语料，蒸馏成逐句有出处、置信度分层、冲突留痕的可信知识，精准逆向出感兴趣的目标。第一个验证场景是 IOS 教员操作台，该场景的交付物是软件规格书，用来直接指导真实工程开发。

问题的内核是信任链：输入不可信（官方手册有版本滞后，培训材料有错误，博客只有粗糙线索，LLM 会批量犯错），输出却必须可信（下游是真实开发决策，写错一行规格的代价是真金白银）。管道里所有纪律，出处强制、置信度分级、线索隔离、冲突并存、盲评门槛，本质都在做同一件事：把 LLM 生成内容的信任等级从看起来对提升到工程可依赖。这也是它不归属 RAG 的根本原因：RAG 解决的是找到，这套架构解决的是敢用。

## 二、归属判断总览：目的层与手段层分开回答

归属问题必须拆成两层，混在一起答会得出片面结论。

- 目的层（解决什么问题）：与三个成熟领域同构。开源情报分析（OSINT）提供可信度方法论，循证医学系统综述提供流程纪律，软件设计恢复（Design Recovery）提供目标与术语体系。
- 手段层（用什么技术实现）：归属 LLM 驱动的知识图谱构建（Knowledge Graph Construction, KGC）与结构化信息抽取，工程形态是人机回环的知识工程管线。这个子领域 2023 到 2026 年爆发，锚点是 Microsoft GraphRAG，见 [donto 行业扫描](https://donto.org/reports/donto-company-vision-appendix-2026-06-01)。

一句话定位：以软件设计恢复为目标，用 OSINT 情报分析做可信度方法论，用循证综述做流程纪律，以 LLM 知识图谱构建为技术手段，工程形态接近 Deep Research 的可信度强化版。三个老领域各出一个零件，LLM 出发动机，组装是自己的。

## 三、目的层同构领域之一：开源情报分析（OSINT）

这是最贴近设计初衷的领域。两者回答的是同一个问题：目标无法直接接触，手里只有真假混杂的公开资料，要产出带信源分级和置信度的正式判断，供高代价决策使用。

### 3.1 领域基本情况

情报界按收集手段分工，OSINT 指从公开可获取来源（出版物、手册、网站、广播、商业数据库、灰色文献）收集并分析产出的情报，与人力情报（HUMINT）、信号情报（SIGINT）、图像情报（IMINT）并列。公开资料长期被视为二等情报来源，直到实践中发现大部分答案其实都在公开资料里，这个处境与逆向工程场景里官方手册、培训材料、博客的地位完全同构。

### 3.2 逐项机制对应

| OSINT 机制 | 内容 | 本架构对应物 |
| --- | --- | --- |
| Admiralty 信源分级 | 1939 年英国海军情报处首创，现为 NATO 标准（STANAG 2511）。两轴独立打分：信源可靠性 A 到 F，信息可信度 1 到 6。每条情报必须带双评级，未经评估不算情报 | 权威性维度（厂商官方到二手博客）是一轴，置信度字段是另一轴，同样双轴分离。主文档 §9.1 定为同构 |
| ICD 203 分析标准 | 美国国家情报总监办公室 2015 年发布。情报判断必须显式表达高、中、低置信度，并写明依据（信息质量、来源佐证、假设） | 置信度三级，以及推理补全四环节中依据必须写进条目、不许写据了解据说 |
| ACH 竞争性假设 | Heuer 在 CIA 成型的方法。面对互斥解释，列出全部假设，寻找能证伪的证据，不急于选定唯一解释 | 同级冲突双条目并存、不擅自取舍、留待人工仲裁（§6.3） |
| 线索与证据的区分 | 低等级来源只能提供 lead（去哪里查），不能直接写入判断 | 原则三：线索不等于证据，线索层永不进证据链 |
| 评审传统 | 重要评估须经非作者视角挑战（red team、devil's advocate），作者自查不可靠 | 盲评必须由懂行的非作者执行（§8.3） |
| 产物形态 | intelligence assessment：有定论、带分级、可问责的正式判断，区别于日常快报 | 规格书（冻结、盲评、交付）与日常随问随答的区分（§8.3） |

### 3.3 参考物

纯方法论领域，没有开源工程。核心读物：Heuer《Psychology of Intelligence Analysis》（CIA 1999，CIA 官网公开免费）、ICD 203 原文（dni.gov 公开）、NATO Admiralty 分级的公开介绍资料。主文档 §9.1 已把这些先例列为同构项，本节是把对应关系展开到机制细节。

## 四、目的层同构领域之二：循证医学系统综述

流程纪律上最贴近的领域。系统综述要回答：面对海量质量参差的文献，关于某个问题的可靠结论是什么。逐项对应：

- 协议预注册（PROSPERO）：动工前冻结研究方案，对应原则二结构先行。
- 两级筛选（PRISMA 流程）：先按标题摘要筛掉绝大多数，再对幸存者读全文，对应 L1 分级不读全文。
- 数据提取表：每篇纳入研究按预定义字段表逐篇提取，对应 §6.1 条目字段表。
- 偏倚风险评估与 GRADE 证据分级：对每项证据的质量分级，对应置信度体系。
- 参考工具：ASReview（开源，主动学习辅助筛选，主文档已引用）。

LLM 时代这个领域的商业化代表是 [Elicit](https://elicit.com)，它是目前与本架构形态最接近的真实产品，见 [2026 年评测](https://toolcurrent.com/tools/elicit)。三个对应点几乎严丝合缝：用户自定义提取列对应领域定制字段表，每个提取值附原文 supporting quote 对应 SUPPORTS 出处强制，公布提取准确率指标对应 §9.3 软肋里缺的实测数据文化。Elicit 是闭源商业产品，参考其工作流与交互形态即可，读完它的帮助文档就能拿走大部分形态经验。

## 五、目的层同构领域之三：软件设计恢复（Design Recovery）

目标层最贴近的领域，也是这套架构在学科谱系里的正式户口。

### 5.1 术语与定义

逆向工程在软件工程学科的标准定义出自 Chikofsky 与 Cross 1990 年的论文《Reverse Engineering and Design Recovery: A Taxonomy》（IEEE Software, 7(1), 13-17，DOI: 10.1109/52.43044，被引 3600 余次）：分析目标系统，识别组件及其相互关系，并在更高抽象层次或以另一种形式创建系统表示的过程。Design Recovery（设计恢复）是其关键子领域：结合外部知识（文档、领域经验、人员访谈）与系统本体分析，重建系统的设计意图与抽象规格。

一个常被忽略的细节：Chikofsky 的分类里，设计恢复本来就明确包含使用外部信息（包括文档）的路径。所以从文档恢复规格不是逆向工程的异类，而是教科书定义内的合法路径。只是 1990 年代的 NLP 理解不了操作级文本，工业实践主流才走向代码路径（反编译、静态分析、程序切片），文档路径沉寂了三十年。

### 5.2 相关学科与工业场景

- 相关学科：程序理解（Program Comprehension，有 ICPC 国际会议）、软件维护与演化（ICSME 会议）、软件考古（Software Archaeology，对遗留系统的考察实践）。
- 工业场景：遗留系统现代化（文档缺失或过时的系统迁移重写）、供应商解绑、兼容实现、安全审计。
- 工具现状：代码路径工具厚实（Ghidra、IDA Pro、radare2 等反编译与静态分析工具），文档路径在 LLM 之前没有可行的工业开源工程。经 2026-09-10 检索核实，specification recovery 与 specification mining 方向的公开工作仍集中在代码侧与代码生成侧（如 SpecFirst），文档侧是工程真空。

### 5.3 净室逆向工程：规格书为什么必须是定稿

净室逆向工程（clean-room reverse engineering）是法律上规避版权风险的兼容实现方法，主文档 §9.1 已列为目标层先例，这里展开它的工程细节。两组人物理隔离：分析组研究目标系统，产出规格文档；实现组从未接触目标本体，只读规格文档开发。经典案例是 1980 年代 Phoenix Technologies 净室重实现 IBM PC BIOS，奠定了 PC 兼容机产业。延续传统包括 Wine 对 Windows API 的净室实现、各开源操作系统对 POSIX 文档的实现。

净室流程对本架构的意义：规格文档是两组之间的唯一桥梁，实现组不许回头查原始资料。这解释了为什么规格书必须是完整、自足、冻结、通过盲评的定稿，而不是随问随答的临时输出。规格里一处幻觉就是产品里一处缺陷，而且实现组没有任何手段发现它。主文档 §8.3 对规格书与日常查询的区分，与净室纪律完全同构。

### 5.4 LLM 改变的东西

操作级自然语言（手册、培训材料）第一次可以被机器成批理解。老问题（设计恢复）遇到新引擎（LLM 阅读理解），这就是本架构的时代位置：不是发明新问题，而是让一条沉寂三十年的合法路径重新可行。

## 六、手段层定位：LLM 知识图谱构建与 source-grounded 抽取

- 主归属：LLM-based Knowledge Graph Construction。这个子领域 2023 到 2026 年爆发，是应用型 LLM 基础设施里最热的方向之一，锚点 Microsoft GraphRAG 约 33k stars（2026 年中数据）。
- 精确坐标：schema 引导、带出处强制、人机回环的抽取管线。2026 年这个交叉点上出现了与本架构高度重合的趋势：source-grounded extraction，每条抽取结果必须锚定原文位置。代表是 Google 的 LangExtract，定位从 AI 魔法变成可审计数据管道，见 [Groundy 评测](https://groundy.com/articles/google-langextract-source-grounding/)。这与 SUPPORTS 边思想一致，说明出处纪律踩在了潮流方向上。
- 另一个旁证：持久知识库对抗逐次检索的思路正在成型，有人专门比较多个框架哪个适合把语料一次性编译成持久互联的知识体，见 [Open-Source Frameworks for an LLM Wiki](https://forwardic.org/blog/posts/open-source-frameworks-for-an-llm-wiki/)。建库一次、随用随查正是这个理念。
- 不属于什么：不是 RAG 应用（不做相似度召回），不是 agent 框架问题（agent 只是交互件），不是文档解析问题（MinerU 那一层只是 L0）。
- LLM 原生形态近亲：Deep Research 类系统（OpenAI Deep Research、Gemini 同名产品，开源代表 STORM 与 gpt-researcher），见 [2026 年开源研究助手盘点](https://listenlabs.com/articles/best-open-source-gpt-assistants/)。形态接近，但它们没有信源分级、线索隔离、置信度体系、覆盖率审计和冲突仲裁。它们是快速综合，本架构是可信蒸馏。零件可拆，可信度层它们给不了。

## 七、可参考的开源工程与产品

按用途分组，每个注明参考哪部分、警惕哪部分。

建库侧核心参照（重点三个）：

- [google/langextract](https://github.com/google/langextract)：Google 维护，Apache 2.0，2026 年仍活跃。核心参考 source grounding 实现，即抽取结果如何锚定原文精确位置并可视化对质。对应 L2 蒸馏和 §7.1 出处校验，最需要细读。
- [OpenSPG/KAG](https://github.com/OpenSPG/KAG)：蚂蚁的 schema 引导知识图谱构建框架。参考如何用预定义 schema 约束 LLM 抽取、如何做知识融合。对应原则二结构先行和 L1.5 术语对齐。
- [microsoft/graphrag](https://github.com/microsoft/graphrag)：参考分块、实体关系抽取、索引管线的工程组织。警惕消费侧（社区摘要、全局查询），那是为召回率服务的，不要学。

增量与演化机制：

- [HKUDS/LightRAG](https://github.com/HKUDS/LightRAG)：增量建图（新文档合并进已有图谱而非全量重建），正好回应 TODO-3 条目去重与合并的候选召回机制。
- [getzep/graphiti](https://github.com/getzep/graphiti) 与 [topoteretes/cognee](https://github.com/topoteretes/cognee)：时序演化和知识底座的工程化做法，对应 supersedes 历史不抹除的设计。

形态近亲（Deep Research 类）：

- [stanford-oval/storm](https://github.com/stanford-oval/storm)：斯坦福出品，多来源生成带引用的维基风格长文，特色是多视角问题规划。可参考其提问生成机制，用于盲区消化 agent：围绕盲区清单自动生成多角度追问。
- [assafelovic/gpt-researcher](https://github.com/assafelovic/gpt-researcher)：最流行的开源 deep research agent。参考其规划、检索、阅读、综合、带引用组装报告的任务编排。

产品形态参照：

- [Elicit](https://elicit.com)：见 §四。字段表加出处加准确率文化的工作流形态。

人机回环与标注侧：

- Snorkel（弱监督）：对应 §3.3 第 3 步规则固化。注意 Snorkel 已转商业化平台，参考其开源库的思想即可。
- [Label Studio](https://github.com/HumanSignal/label-studio) 或 doccano：审核工作台 UI 参照，术语仲裁、冲突裁决、盲评的交互形态可对标标注平台的评审模式。
- ASReview：对应 L1 分级的两级筛选加主动学习，主文档已引用。

L0 文档结构化：MinerU（已在用）、IBM Docling、unstructured，这一层不需要新参考。

方法论读物：Heuer《Psychology of Intelligence Analysis》、ICD 203 原文、PRISMA 流程说明。

## 八、搜不到现成工程的空白地带

以下组件经检索确认没有对应开源物，要自己造：

- 从文档逆向规格的完整管线。开源工程几乎全在从代码恢复规格一侧，文档侧基本空白（§5.2）。
- 权威性乘相关性乘信息密度的三轴分级、线索层与证据链隔离、断言三态闭环、冲突并存不擅自取舍。这些来自情报分析和系统综述方法论，代码界还没人移植。

这意味着差异化不在任何单一零件，而在组装方式，与主文档 §9.3 诚实清单的结论一致。空白同时是机会：文档侧设计恢复是工程真空，先建成并验收的知识库本体就是护城河。

## 十、参考纪律（冷峻提醒）

- 参考 GraphRAG 与 Deep Research 生态时保持清醒：它们的优化目标是问答召回率与综合速度，本架构的目标是逐句覆盖率与可信度。零件可以拆走，消费方式不要引入。§7.2 的五步确定性查询已经是正确答案，不需要向任何 RAG 框架看齐。
- 参考顺序建议：方法论读情报分析（深化已有优势），产品形态拆 Elicit（字段表加出处加验收的交互），工程管线拆 STORM 和 gpt-researcher（agent 编排与报告组装），建库零件拆 langextract 和 KAG。四类参考各取一层，互不重叠。
