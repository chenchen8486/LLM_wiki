# 多媒体信息抽取：架构设想

　　在线阅读（GitHub Pages）：[多媒体信息抽取：架构设想（阅读版，含 13 章演示动画）](https://chenchen8486.github.io/LLM_wiki/docs/1_2_%E5%A4%9A%E5%AA%92%E4%BD%93%E4%BF%A1%E6%81%AF%E6%8A%BD%E5%8F%96%EF%BC%9A%E6%9E%B6%E6%9E%84%E8%AE%BE%E6%83%B3.html)

　　首次使用需在仓库 Settings → Pages 选 Deploy from a branch，分支 master、目录 /(root)，保存后等一两分钟即可访问。第 13 章演示依赖 docs/gif/ 下的帧图，已随仓库推送。

　　这是一个架构设计文档项目，不是代码工程。核心内容是一套知识管道的设计：把不同质量的文档语料（官方手册、培训材料、博客、播客转录等）逐句覆盖地采集、分级、对齐、蒸馏，逆向出一份可逐条对质的知识底账，每条结论都记着出自哪份文档哪一节。第一个落地场景是逆向可信的软件规格书，换成其他逆向目标时管道机制不变。

　　设计的三条基本原则：

1. 逐句覆盖，不建向量库做相似度召回（反 RAG）。
2. 输出结构先于语料定稿。
3. 线索永远不等于证据。

　　tools/ 下的工具：

- `md2pdf.py`：Markdown 转 PDF，用法 `.venv/Scripts/python tools/md2pdf.py docs/文件.md`。
- `fix_archify_arrows.py`：修复 archify 交付 HTML 的箭头朝向，每次重新出图后重跑。
- `feishu-cli/`：飞书文档命令行工具，用于与飞书文档互转。
- `mermaid.min.js`：md2pdf 与阅读版 HTML 共用的 mermaid 渲染引擎，固化副本，不要移动或删除。

## 阅读顺序建议

1. 想快速看懂架构：打开 `docs/1_2_...html` 阅读版，或直接看顶部的在线阅读链接。
2. 想直观看全链路怎么跑：看阅读版第 12 章的六张 GIF，再用第 13 章的逐帧播放器慢放细读。
3. 要查字段、格式、命令等细节：读 `docs/1_1_...md` 主文档，细节冲突时以它为准。
4. 想了解这套设计能怎么落地、属于什么技术领域：读 2 和 3。

## 待做：外部工程参考

　　Google 的 Knowledge Catalog 工程与本项目同属知识当代码管的思路，有三块设计值得后续借鉴，登记为待做（2026-10-21）：

1. 条目时效机制。OKF 的 frontmatter 有 sources（逐源可信度）、verified、stale_after（过期时间）字段。本项目 entries.jsonl 目前缺时效维度，资料会过时，后续可加 stale_after 类字段，让过期条目自动进入复核范围。
2. 双向同步参考。mdcode 工具实现本地文件与云端元数据服务的 pull、push、status 同步，带冲突检测与 dry-run。本项目将来若迁图数据库或接入服务化存储，可参照其设计。
3. 自动生成 agent 技能文件。mdcode 能从语义模型自动生成 SKILL.md。本项目的领域字段表加术语登记表已构成一份领域语义模型，将来可据此生成查询 agent 的 SKILL.md，让 agent 开箱即会用本库。
